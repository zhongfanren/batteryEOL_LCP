# ISU-ILCC 单来源、多协议候选集（2026-10-26）

## 研究总体

从现有 BatteryLife v4 `MIX_large` 的固定 T=100 合格池中，取全部 239 块 `ISU_ILCC` 电芯。资格包含原加载器要求的寿命标签 EOL>100，以及100个可用前缀；不根据预测误差或期望实验结果额外筛选。每块电芯在第 100 周期形成一个 EOL 预测目标。数据文件仍留在 `C:\BatteryLife_v4\ISU_ILCC`，本目录的 `isu_ilcc_t100_candidate.json` 是可复现的电芯清单和拟议划分，不复制约 11 GB 的曲线文件。生成程序是 `build_isu_candidate.py`。

2026-10-28补充核查：官方划分列出240块，本地文件与标签键也都是240个。`ISU-ILCC_G40C3.pkl`的发布寿命标签为16，原加载器记为0个可用前缀，因此排除；其余239块全部入选。这里没有先按曲线相似性聚类再选样本。旧冻结JSON里“no label-based filtering”是过于笼统的历史表述，应按本段理解为“任务资格之外，不做基于标签/误差表现的额外筛选”；冻结清单保持原始字节，避免破坏既有实验指纹。

原始 [ISU-ILCC 数据集说明](https://iastate.figshare.com/articles/dataset/_b_ISU-ILCC_Battery_Aging_Dataset_b_/22582234) 将充电倍率、放电倍率、放电深度列为变化的实验因素。本地 239 块电芯构成 61 个文件名 `G` 条件：56 组有 4 块，5 组有 3 块。全部记录为石墨负极、NMC 正极、0.25 Ah 聚合物电芯，电压上下限为 4.2/3.0 V；同一 `G` 内的充放电**倍率序列**一致。这比直接拼接不同来源的相似协议更容易定义一个研究总体，但不等于不同 `G` 条件或批次下的电芯天然可交换。

## 已发现的元数据问题

- 46/61 个 `G` 条件的完整充放电协议字段在重复电芯间不同，核查显示倍率序列仍一致，变化主要在每块电芯记录的 SOC 端点。原值完整保留在 JSON 清单中。
- [BatteryLife v5 发布记录](https://zenodo.org/records/15300265) 明确说修正了 ISU-ILCC 的部分 `SOC_interval`。当前实验数据是 v4；在原始参数表或 v5 元数据交叉核验以前，不应把 v4 SOC 端点当作准确的放电深度，也不应用其训练局部距离。
- 原始发布页面描述的电芯数量与 BatteryLife 处理文件、T=100 筛选口径不同；这里的 239 是**本地任务合格数**，不是对原始发布总量的复述。

## 拟议实验划分

`isu_ilcc_t100_candidate.json` 用种子 `20261026` 对 239 个电芯 ID 做一次与标签无关的随机划分：97 train、20 dev、61 calibration、61 test。不同阶段无电芯重复；`G` 条件允许跨阶段，因为研究目标是**已知协议条件的混合总体中随机抽取新电芯**，不是对全新 `G` 条件的外推。由于是不分层随机划分，并非每个 `G` 都同时出现在 train、calibration、test；报告中需列出各组样本数，不能声称每组 90% 覆盖。

预测器必须只用这里的 train 拟合、dev 选 epoch，再冻结；先前 `MIX_large` 的检查点含有这些电芯，不能复用。固定 T=100，一块电芯只产生一条 calibration/test 分数。首个比较应包括普通 Split CP、预先固定距离和带宽的 LCP，以及逐 `G` 的误差与覆盖描述。当前基于预测值的简单加权分位数 LCP 仅是探索性比较，不具有自动的有限样本覆盖保证。

随机分配允许对这个**固定合格池内、随机分配的测试电芯**作设计条件下的覆盖解释，前提是预测器和全部方法选择不利用 calibration/test 标签。要把保证推广至未来新电芯，仍需定义并支持它们来自相同协议混合总体的抽样假设。此前混合试验已经查看过部分这些电芯的测试标签，也用同一底层数据选择过预测器类别，所以这个候选集的首轮结果应标为**探索性**，不能说是全新的确认性测试。

## 当前状态

清单、元数据、拟议划分已构建；尚未用此划分训练预测器或计算 CP/LCP。更严格的物理协议解释仍需对照原始 `G` 参数表，尤其是放电深度。若后续改变入选规则或划分，应写入新的版本文件，保留本次清单与种子。
